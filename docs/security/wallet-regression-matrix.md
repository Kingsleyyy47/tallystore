# Wallet Regression Matrix

Prepared: 2026-09-19

This matrix tracks the mandatory incident scenarios from the implementation
prompt. It separates source-level coverage from tests that still require
staging Supabase/Postgres, provider mocks/sandboxes, concurrency harnesses, or
owner production evidence.

Status labels:

- `STATIC_SOURCE_COVERED`: covered by `npm run security:wallet`.
- `LOCAL_MIGRATION_STATIC_PASSED`: covered by
  `npm run security:wallet:migrations`; this proves incident migration text
  does not reintroduce dangerous browser grants, function execution, disabled
  RLS, or unpinned security-definer search paths. It does not replace executing
  the migrations or testing effective grants in Postgres.
- `LOCAL_MONEY_BOUNDARY_PASSED`: covered by
  `npm run security:wallet:money-boundaries`; this proves local amount,
  currency, debit-signing, JSON-boundary, and database-style money constraint
  policy only. It does not replace executing database constraints.
- `LOCAL_MODEL_SEQUENCE_PASSED`: covered by
  `npm run security:wallet:model`; this proves model-level invariants only and
  does not replace real database locking/provider tests.
- `LOCAL_CONCURRENCY_MODEL_PASSED`: covered by
  `npm run security:wallet:concurrency`; this proves local race/interleaving
  policy only and does not replace real Postgres row-lock tests.
- `LOCAL_ROUTE_DECISION_PASSED`: covered by
  `npm run security:wallet:routes`; this proves local hostile-payload and
  idempotency policy only and does not replace deployed route tests.
- `LOCAL_ROUTE_SOURCE_ORDER_PASSED`: covered by
  `npm run security:wallet:route-source-order`; this proves source ordering for
  mapped route files only and does not replace deployed endpoint tests.
- `LOCAL_RUNTIME_BOUNDARY_SOURCE_PASSED`: covered by
  `npm run security:wallet:runtime-boundaries`; this proves targeted
  repository source boundaries for admin unfreeze backing checks, crypto
  manual-review holds, webhook signature-before-mutation ordering, debit-before
  provider dispatch, original-debit refund provenance, and completed-only value
  reveal. It does not replace deployed endpoint, provider, or database tests.
- `LOCAL_TRUSTED_PRINCIPAL_PASSED`: covered by
  `npm run security:wallet:trusted-principal`; this proves local
  source-of-funds principal/refund/restoration policy only and does not replace
  database execution, provider proof, or deployed route tests.
- `LOCAL_SUPPLIER_OUTCOME_PASSED`: covered by
  `npm run security:wallet:suppliers`; this proves local supplier-outcome
  policy only and does not replace provider sandbox/dashboard tests.
- `LOCAL_PROVIDER_DECISION_PASSED`: covered by
  `npm run security:wallet:providers`; this proves local provider-decision
  policy only and does not replace provider sandbox/dashboard tests.
- `LOCAL_PROVIDER_ADAPTER_MOCK_PASSED`: covered by
  `npm run security:wallet:adapters`; this proves no-network mock providers
  are not called for paused/frozen/insufficient/conflicting requests and are
  not redispatched on exact idempotency replay. It does not replace real
  provider contracts or deployed route tests.
- `LOCAL_ADMIN_REVIEW_MODEL_PASSED`: covered by
  `npm run security:wallet:admin-review`; this proves local approved-credit
  and unsuspend-review policy only and does not replace staging admin workflow
  or production reviewer evidence.
- `LOCAL_ADMIN_UI_MODEL_PASSED`: covered by
  `npm run security:wallet:admin-ui`; this proves local admin date-label and
  transaction-display policy only and does not replace browser visual QA.
- `LOCAL_CUSTOMER_UI_MODEL_PASSED`: covered by
  `npm run security:wallet:customer-ui`; this proves local customer wallet and
  dashboard transaction-display policy only and does not replace browser visual
  QA.
- `LOCAL_FROZEN_ACCESS_MODEL_PASSED`: covered by
  `npm run security:wallet:frozen-access`; this proves local frozen-account
  read-only route/history/support policy only and does not replace deployed
  route tests or browser visual QA.
- `LOCAL_FULFILLMENT_DECISION_PASSED`: covered by
  `npm run security:wallet:fulfillment`; this proves local fulfillment policy
  only and does not replace real worker/outbox/provider tests.
- `LOCAL_OUTBOX_MODEL_PASSED`: covered by
  `npm run security:wallet:outbox`; this proves local durable-dispatch and
  worker-claim policy only and does not replace real queue/database workers.
- `LOCAL_RESERVATION_MODEL_PASSED`: covered by
  `npm run security:wallet:reservations`; this proves local reservation
  hold/capture/release/refund-principal policy only and does not replace
  deployed route integration or Postgres RPC execution.
- `LOCAL_RECONCILE_OFFLINE_PASSED`: covered by
  `npm run security:wallet:reconcile-offline`; this proves offline CSV
  deduplication, derived-file exclusion, and order/transaction double-count
  handling only. It does not prove production provider funding or supplier cost.
- `LOCAL_REFUND_CONSERVATION_PASSED`: covered by
  `npm run security:wallet:refunds`; this proves local refund-cap,
  partial-refund, idempotent replay, changed-payload conflict, owner-mismatch,
  and missing-original-debit policy only. It does not replace database/provider
  concurrency tests.
- `LOCAL_DEPLOYED_VERSION_EVIDENCE_PASSED`: covered by
  `npm run security:wallet:deployed-versions -- --self-test`; this proves the
  deployed-version evidence template and validator fail closed for missing,
  pending, and secret-looking proof. It does not prove live deployment versions
  until the owner fills and validates dashboard evidence after deployment.
- `DEPLOYED_SMOKE_CREATED_NOT_RUN`: covered by
  `scripts/wallet-deployed-smoke-test.mjs`, but not run here because no deployed
  base URL and owner-controlled smoke auth header are available.
- `STAGING_SQL_CREATED_NOT_RUN`: covered by
  `docs/security/wallet-db-security-test-pack.sql`, but not run here because no
  local Supabase/Postgres database is available.
- `DB_CONCURRENCY_RUNNER_CREATED_NOT_RUN`: covered by
  `scripts/wallet-db-concurrency-runner.mjs`, but not run here because no
  owner-controlled staging/local Postgres database, `psql`, and dedicated test
  fixture wallets are available.
- `PATCH_IMPLEMENTED_TEST_PENDING`: repository patch exists; stronger runtime
  test still required.
- `PROVIDER_TEST_PENDING`: requires live provider sandbox/dashboard or
  route-specific runtime proof. Local no-network provider mocks are labeled
  separately where they have passed.
- `CONCURRENCY_TEST_PENDING`: requires real database locking/fault tests.
- `PRODUCTION_OWNER_PENDING`: owner must verify deployed versions/config.
- `NOT_IMPLEMENTED_AS_FULL_TEST`: documented as a remaining gap.
