# Wallet Mutation Map

Prepared: 2026-09-19

This map is source evidence for the wallet incident prompt. It records paths
that can create, move, display, or approve wallet value. It is not proof of live
production safety until the owner deploys the matching migrations/functions and
runs the production checks.

Classification labels:

- `LOCALLY_VERIFIED_SAFE`: source invariant is covered by `npm run security:wallet`.
- `PATCH_IMPLEMENTED`: repository patch exists, but DB/provider proof is pending.
- `PAUSED`: route is closed or fails closed by default.
- `OWNER_PRODUCTION_CHECK_REQUIRED`: live grants, function versions, provider
  dashboards, or logs must be checked by the owner.
- `HISTORICAL_CAUSE_UNPROVEN`: source review does not prove what happened in
  the past incident.

## Required Field Coverage

The incident prompt requires each wallet mutation path to be reviewed with
these fields. The tables below use shorter columns, so this section maps the
field names explicitly:

| Prompt field | Where it is recorded in this map |
| --- | --- |
| Path ID | First column of each table. |
| File/function and entry point | `Entry point` plus the path-specific notes. |
| External or internal caller | `Caller and auth`, `Source of funds validation`, or path notes. |
| Request entry point and authentication | `Caller and auth`, source validation notes, and route inventory. |
| Runtime database role | `Runtime DB role` where the path writes database state; server Edge Functions use the service role unless noted. |
| Schema, table, column, SQL/RPC involved | `Mutation target`, `Ledger behavior`, and function/RPC names. |
| Input ownership and amount validation | Source-of-funds and debit/refund behavior notes. Route-level hostile input coverage is tracked in the regression matrix. |
| Source-of-funds validation | Payment/funding table and trusted-credit rule. |
| Transaction and locking behavior | Controlled writer boundary; `apply_wallet_transaction` locks the profile row with `FOR UPDATE`. |
| Idempotency mechanism | Controlled writer, payment/funding, and purchase debit rows describe deterministic idempotency keys and conflict handling. |
| Ledger and balance writes | `Ledger behavior`, `Debit/refund behavior`, and mutation target. |
| Security-state effect | Current control and classification; freezes/review are called out on unbacked funds, chargebacks, and fraud scan. |
| Local exploit or regression test | Classification plus `wallet-regression-matrix.md` and `wallet-test-report.md`. |
| Production evidence still needed | Final column of each table. |

If a future wallet writer cannot fill every field above, treat it as
`UNKNOWN` and keep the route paused until the missing evidence is supplied.

## Runtime And Evidence Limits

- `HISTORICAL_CAUSE_UNPROVEN`: this map proves repository controls exist; it
  does not identify the historical write or fake-payment path without live logs,
  provider records, and deployed schema evidence.
- `LOCAL_DB_SECURITY_TESTS_PENDING`: Docker/local Supabase was unavailable here,
  so grant/RLS/trigger/locking tests must run in staging or owner-controlled DB.
- `PROVIDER_TESTS_PENDING`: webhook/provider behavior must be checked with
  sandbox or mocked adapters before reopening paused routes.
- `PRODUCTION_VERIFICATION_PENDING_OWNER`: production migrations, function
  versions, Vercel routes, env flags, provider dashboards, and old workers remain
  owner-controlled verification items.
