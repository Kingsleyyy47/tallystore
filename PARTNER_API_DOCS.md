# TallyStore Partner API

Private API for trusted partners to load TallyStore catalogue items, show live prices and stock on their own website, create customer checkouts through TallyStore's PocketFi gateway, and receive signed webhook updates.

## Base URL

```text
https://tallystore.org/api/partner-api
```

All requests are `POST` JSON requests.

## Authentication

Send the API key in one of these ways:

```http
x-tally-api-key: tly_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

or:

```http
Authorization: Bearer tly_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Each partner is limited to the sections enabled by TallyStore admin. If a section is not enabled, catalogue and order requests for that section are rejected.

## Important Rules

- Do not hardcode prices from old catalogue responses. Always use the latest `catalogue` response before showing checkout totals.
- TallyStore calculates final price server-side.
- TallyStore validates stock server-side.
- Out-of-stock products may appear in catalogue with `availability: "out_of_stock"` so partners can display them, but they cannot be purchased.
- Use a unique `idempotency_key` for every checkout/order attempt.
- Crypto uses `create_order`, not PocketFi bank transfer checkout.
- Webhook secrets are generated by TallyStore admin and shown once. The partner should store it securely.
- TallyStore does not send the webhook secret in webhook requests.
- If a partner loses the API key or webhook secret, TallyStore admin must generate a new API key + webhook secret pair.
- TallyStore admin can edit the partner webhook URL later without changing the existing API key or webhook secret.

## Response Shape

Successful responses use:

```json
{
  "success": true,
  "data": {}
}
```

Failed responses use:

```json
{
  "success": false,
  "error": "Error message"
}
```

## 1. Catalogue

Use this to fetch live items the partner is allowed to sell.

### Request

```json
{
  "action": "catalogue"
}
```

Optional single-section request:

```json
{
  "action": "catalogue",
  "section": "products"
}
```

Allowed section values:

```text
products
sms
social_boost
bills_airtime
giftcards
crypto
telegram_stars
```

Gift card catalogue also supports search:

```json
{
  "action": "catalogue",
  "section": "giftcards",
  "search": "amazon",
  "limit": 20
}
```

## 2. Partner Balance

Use this only for wallet-funded partner orders. PocketFi checkout does not require partner wallet balance.

### Request

```json
{
  "action": "balance"
}
```

### Response

```json
{
  "success": true,
  "data": {
    "balance_ngn": 0,
    "currency": "NGN"
  }
}
```

## 3. Create PocketFi Checkout

This creates a TallyStore order and returns a permanent PocketFi bank account for the partner's customer. The customer transfers the exact amount. When PocketFi confirms payment to TallyStore, TallyStore fulfills the order and sends a webhook to the partner.

### Product Checkout

```json
{
  "action": "create_checkout",
  "item_type": "product",
  "item_id": "product-group-id",
  "quantity": 1,
  "customer_reference": "partner-customer-123",
  "customer_name": "Customer Name",
  "customer_email": "buyer@example.com",
  "customer_phone": "08000000000",
  "partner_reference": "partner-order-1001",
  "idempotency_key": "partner-order-1001-create-checkout"
}
```

## 4. Create Wallet-Funded Order

This debits the partner wallet immediately and fulfills directly. Most partners should use `create_checkout` instead.

### Request

```json
{
  "action": "create_order",
  "item_type": "product",
  "item_id": "product-group-id",
  "quantity": 1,
  "customer_email": "buyer@example.com",
  "partner_reference": "partner-order-2001",
  "idempotency_key": "partner-order-2001-create-order"
}
```

The same item-specific fields from `create_checkout` apply to `create_order`.

## 7. Product Credential Delivery

When a product order completes, credentials are returned in `data.response_payload.accounts`.

The same account format used by TallyStore bulk uploads is:

```text
username,password,two_fa_code,email,email_password
```

Example completed product response data:

```json
{
  "status": "completed",
  "response_payload": {
    "product_name": "Example Account",
    "category": "Accounts",
    "accounts": [
      {
        "username": "user123",
        "password": "pass123",
        "two_fa_code": "2FAKEY",
        "email": "mail@example.com",
        "email_password": "mailpass123",
        "recovery_email": null,
        "recovery_email_password": null,
        "additional_info": null
      }
    ]
  }
}
```

## 8. SMS Code Delivery

When an SMS order becomes active, the partner receives:

```json
{
  "status": "active",
  "response_payload": {
    "service_name": "Service Name",
    "phone_number": "+1234567890",
    "raw_phone_number": "1234567890",
    "expires_at": "2026-09-10T00:20:00.000Z"
  }
}
```

After the OTP arrives, `order_status` can return:

```json
{
  "status": "completed",
  "response_payload": {
    "code": "123456",
    "completed_at": "2026-09-10T00:10:00.000Z"
  }
}
```

## 9. Webhooks

TallyStore sends webhooks to the partner's saved webhook URL. The webhook URL can be edited later in TallyStore admin without changing the partner API key or webhook secret.

### Headers

```http
Content-Type: application/json
User-Agent: TallyStore-Partner-API/1.0
X-Tally-Event: partner.order.completed
X-Tally-Partner-Id: partner-id
X-Tally-Timestamp: 1788998400
X-Tally-Signature: sha256=hex_hmac_signature
```

### Signature Verification

The signature is:

```text
HMAC_SHA256(webhook_secret, timestamp + "." + raw_request_body)
```

Partners should reject webhooks if:

- `X-Tally-Signature` is missing or invalid
- `X-Tally-Timestamp` is too old
- the same event/order update was already processed

### Node.js Verification Example

```js
import crypto from "crypto";

function verifyTallyWebhook({ rawBody, timestamp, signature, webhookSecret }) {
  const expected =
    "sha256=" +
    crypto
      .createHmac("sha256", webhookSecret)
      .update(`${timestamp}.${rawBody}`)
      .digest("hex");

  return crypto.timingSafeEqual(
    Buffer.from(signature),
    Buffer.from(expected)
  );
}
```

### Webhook Payload

```json
{
  "event": "partner.order.completed",
  "created_at": "2026-09-10T00:00:00.000Z",
  "partner_id": "partner-id",
  "data": {
    "order": {
      "id": "tallystore-order-id",
      "partner_reference": "partner-order-1001",

      "item_id": "product-group-id",

}
```

## 11. cURL Examples

Catalogue:

```bash
curl -X POST "https://tallystore.org/api/partner-api" \
  -H "Content-Type: application/json" \
  -H "x-tally-api-key: YOUR_API_KEY" \
  -d '{"action":"catalogue","section":"products"}'
```

Create checkout:

```bash
curl -X POST "https://tallystore.org/api/partner-api" \
  -H "Content-Type: application/json" \
  -H "x-tally-api-key: YOUR_API_KEY" \
  -d '{
    "action": "create_checkout",
    "item_type": "product",
    "item_id": "product-group-id",
    "quantity": 1,
    "customer_reference": "partner-customer-123",
    "customer_email": "buyer@example.com",
    "partner_reference": "partner-order-1001",
    "idempotency_key": "partner-order-1001-create-checkout"
  }'
```

Check status:

```bash
curl -X POST "https://tallystore.org/api/partner-api" \
  -H "Content-Type: application/json" \
  -H "x-tally-api-key: YOUR_API_KEY" \
  -d '{"action":"order_status","partner_reference":"partner-order-1001"}'
```

## 12. Admin Notes

TallyStore admin can edit a partner's name, webhook URL, and allowed sections without changing the partner's existing API key or webhook secret.

Generating a new API key also generates a new webhook secret and shows both once. Revoke old keys when a partner should no longer have access.

Existing full API keys are not recoverable because only their hash is stored. Existing webhook secrets are not exposed in the partner list; the admin page only shows whether a webhook secret is stored.
